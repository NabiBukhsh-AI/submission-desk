# ADR-009: Synthetic data in public, real data only in a private pilot

**Status:** accepted. **Applies to:** `data/samples/`, `scripts/make_synthetic_corpus.py`, `scripts/check_pii.py`, `scripts/check_secrets.py`, demo mode in `infrastructure/factory.py`.

## Context

The repository is a portfolio artefact and will be public. Candidate documents
are among the most sensitive things a person shares, and the failure is
unrecoverable: once an address is in a public history it stays there through
every clone and fork, and a later deletion removes the file, not the fact.

## Decision

The public repository contains only generated synthetic candidates. Every
document is built by a script from text in the script, so a reader can see how
it was made, and every address and telephone number in it comes from a range
reserved for fiction. Real pilot documents live outside the repository at a
path the operator chooses, are never committed, and are removed by `purge`
after a retention period.

Three enforcement mechanisms, none of which is discipline:

- **`check_pii`** refuses any file under `data/` outside `data/samples/`, with
  no exemption of any kind, and any address or number not in a reserved range
  anywhere else. A file that must exercise a format with no reserved range
  declares it in its header and is listed on every run.
- **`check_secrets`** refuses `.env` files by name and key-shaped strings by
  pattern, and checks that the example file carries no values.
- **Demo mode** is enforced at the composition root before any adapter
  exists: a configured path to real documents, a remote source, or an inbox
  outside `data/samples/` refuses to start; the source is the synthetic
  corpus and nothing else; there are no sinks and no notifier; the upload
  page is off.

Both scanners run as pre-commit hooks and again in `make check`, so a commit
made with hooks disabled is caught before it merges.

## Alternatives

- **Anonymised real CVs.** Anonymisation of free text is unreliable, and the
  failure is unrecoverable once published.
- **Public CVs from the web.** No consent for this use.
- **A demo flag checked in the interface.** Safe by discipline: one
  environment variable pointing at a pilot folder, and the demo would read
  it.

## Trade-offs

Synthetic documents are cleaner than real ones, which flatters extraction.
Messy cases were written deliberately — a scanned page, two languages, a
contradiction, keyword stuffing — and are still tidier than the real thing.
Extraction quality on real documents is unmeasured and said to be.

## Consequences

The corpus is regenerated by `make seed` rather than committed, so the
readable artefact is the generator. The adversarial corpus and the benchmark
documents are generated the same way for the same reason. Two of the
adversarial samples are plain text rather than PDF because the base fonts
available to the generator cannot encode the zero-width and homoglyph
payloads; the reason is recorded beside them.
